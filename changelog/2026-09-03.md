## 批次 1 — Unit 1：AI provider 统一流式抽象 + anthropic/gemini（refactor）

### 变更摘要

参考 OpenAI Chat Completions SSE、Anthropic Messages SSE、Google Gemini
`streamGenerateContent alt=sse`、Ollama `/api/chat` NDJSON 四家 wire 协议，
将 `@tau/ai` 重构到统一流式抽象上：

- 新增 `packages/ai/src/chat-stream.ts`：四个 wire 各一个共享消费者，
  全部折叠为 provider 无关的 `ProviderStreamEvent` 协议
  （`reasoning_delta` / `text_delta` / `usage`，类型落 `@tau/core`）。
- `AIProvider` 新增**可选** `planStream(ctx, onEvent?)`：流式产出
  reasoning/text 增量并返回与 `plan()` 完全相同（同一 `validatePlanResponse`
  门禁）的 Plan；未实现的 provider 零行为变化。
- 七个 provider 全部落位：openai（SSE + `reasoning_content`）、deepseek
  （harness `StreamChunk` 转发 + 直连路径增量转发，两条路径语义一致）、
  ollama（NDJSON 流式 + `providers.ollama.think` 思考开关）、zai（SDK 非
  流式 → 单次诚实 text 事件，不发明 reasoning）、mock（确定性罐头事件序
  列，离线 demo/测试/截图全链路可用）、**新增 anthropic**（Messages API：
  `x-api-key` + `anthropic-version`，流式 wire，`/v1/models` 发现，
  `providers.anthropic.thinking` + `thinkingBudget` 开启扩展思考且按 API
  契约在思考模式下省略 temperature）、**新增 gemini**（Generative Language
  REST：`x-goog-api-key`，`systemInstruction`，JSON 模式
  `responseMimeType`，thought parts → reasoning，可选 thinkingBudget，
  `GOOGLE_API_KEY`/`GEMINI_API_KEY` 双环境变量回退）。
- `normalizeUsage` 扩展支持 DeepSeek harness / Gemini / Ollama usage 形状；
  `PROVIDER_FIELDS` 增加 `think` / `thinking` / `thinkingBudget`。
- 反射能力扩展：anthropic、gemini 同 wire 实现 `reflect()`。
- registry 注册 7 个内置 provider；双语 README provider 表、
  `packages/ai/README.md` 公开 API、`AGENTS/ai-integration.md` 规则本同步。

### 测试与门禁

- lint=pass（0 warnings 0 errors）typecheck=pass test=pass（528 tests，
  其中新增 8）format=pass build=pass（tsdown + tui + webui vite 客户端
  479 模块）

### 设计决策

- **懒流启动**：NDJSON 头随首个事件发出——provider 不可用等错误发生在
  任何 delta 之前，因此仍可按 /api/plan 的纯 JSON 契约拒绝（503/400），
  永不出现"半开流 + 错误"的混合态。
- **思考缓冲轨**（goal）：thinking delta 先于 round_plan 到达（规划先于
  自身完成），先缓冲在卡片级 liveThinking，round_plan 落地时折叠进该轮
  自己的 ThinkingPanel——时间线保持权威，思考不产生幽灵行。
- **语言检测双实现 + parity 测试**：浏览器无法 import 依赖 node:fs 的
  @tau/tools，镜像一份到 client/lib/language.ts，vitest 同时导入两者
  对 51 个样本逐例断言一致——漂移即红。
- **shiki 渐进式**照旧：任何高亮失败回落纯文本转义渲染（合法终态），
  文件查看器用 `highlightCode()` 动态路径（内容会增长，共享 DOM 升级
  路径的 data-shiki 防重标记不适用）。

## 批次 9 — 文档站部署修复（Pages 站点上线 + 工作流切换为分支发布，fix/docs-pages-branch-publish）

### 问题与根因

| 项   | 内容                                                                                                                                                                                                                                                                                                                              |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 现象 | v0.5.0 系列每次触及 `docs/**` 的 push，"Deploy docs site" 工作流全红（main 与 release 分支），docs 站点无法访问                                                                                                                                                                                                                   |
| 根因 | 工作流假设 `configure-pages enablement: true` 可自建 Pages 站点，但仓库从未启用 Pages：`GITHUB_TOKEN` 调 `POST /repos/{owner}/{repo}/pages` 返回 403 "Resource not accessible by integration"（ Actions 令牌不能创建未启用仓库的 Pages 站点）；维护者现有 fine-grained PAT 亦缺 Pages 权限（同 403），无任何可用凭证能走 API 创建 |
| 结论 | deploy-pages（Actions 模式）在该仓库现状下不可用，需要不改宿主、不提权凭证的发布通道                                                                                                                                                                                                                                              |

### 修复：切换为 gh-pages 分支发布

| 项                            | 内容                                                                                                                                                                                                                                                                                                  |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 站点上线                      | 向 `gh-pages` 分支推送一次构建产物（`.nojekyll` 齐备、base `/Tau/`），GitHub 对公开仓库的分支自动发布机制随之启用 Pages——站点即刻可访问，全程零手工操作                                                                                                                                               |
| 工作流重写                    | `.github/workflows/deploy-docs.yml` 改为：构建（`DOCS_BASE=/Tau/`）→ 冒烟检查（zh/en 首页与 `.nojekyll` 必须存在）→ 在 `docs/.vitepress/dist` 内以孤儿提交 force-push 到 `gh-pages`；仅需 `contents: write`，无 Pages API、无 OIDC；触发收窄为 main（release 线已合并收尾），保留 `workflow_dispatch` |
