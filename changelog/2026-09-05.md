## 批次 2 — webui 页面高度固定 viewport-lock（fix）

### 变更摘要

修复「页面总高度随内部组件高度增长」的布局缺陷：`body`/`#app` 原为
`min-height: 100dvh`，长会话流会撑出整页滚动条，与内部列滚动并存（双滚动）。
SKILL.md/DESIGN.md 布局契约早已声明「viewport-locked (h-dvh app shell)」，
本批次让实现与规范一致：

- `body`：`height: 100dvh` + `overflow: hidden` —— 页面总高度恒等于视口。
- `#app`：`height: 100%`，删除 `min-height`。
- 会话流列 `<section>` 增加 `flex-1`（窄屏 flex 语义；lg 网格下惰性），
  使窄屏下滚动收敛到 `.stream-scroll` 内部；composer 成为列的最后一个
  flex 子元素，常驻可见（删除原 sticky 定位——在非滚动容器中 sticky 已是
  死规则）。

  行为由「one scrolling flow / sticky」更新为「viewport-locked at all
  breakpoints; the conversation stream scrolls」。

## 批次 4 — 设置界面 provider 配置：模型链接查询 + 仅粘贴 key + 防窥掩码（feat）

### 变更摘要

设置面板从「只读视图」升级为「provider 可配置」，实现维护者的三步要求
（选 provider → 粘贴 key → 保存）且**无需手输 URL**：

- **模型链接查询**：新增服务端 `app/webui/src/provider-catalog.ts`——每个
  注册 provider 的默认端点 + 取 key 控制台链接 + keyless 标记（与
  `packages/ai/src/providers/*` 的默认值对齐，头注释强制同步；测试与注册表

  `GET /api/config` 下发 `providerCatalog`，客户端零硬编码。
- **写路径（受控、最小面）**：`POST /api/config/provider {provider, apiKey?,
baseUrl?, activate?}`——复用 `@tau/core` 的 `setConfigValue`（与 CLI
  `tau provider set-key` 同一通道，0600 权限）；Ollama 端点写 `host` 字段、
  其余写 `baseUrl`；`activate` 一键切换活跃 provider；keyless provider
  拒绝 key（镜像 CLI 的 KEYLESS 拒绝）；目录刷新 fire-and-forget（保存
  响应不被不可达端点拖住）；明文 key 只存在于本机请求体与 0600 配置文件，
  从不回显、从不进日志，响应一律标准脱敏 payload。**设计契约变更**：
  「NO write path」更新为「唯一可写切片」，gate/风险策略仍 GET-only。
- **防窥掩码（UI）**：`components/ProviderSetup.vue`——provider 芯片
  （含可用性 ✓/✕ 与 `·key` 标记）、端点自动带出（advanced 折叠项可改）、
