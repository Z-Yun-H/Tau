# Changelog — 2026-09-02

## 变更摘要

将 `packages/ai/src/providers/` 的内部结构按 AGENTS/ai-integration.md 与
AGENTS/architecture.md 治理：把原本寄居在 `mock.ts` 里的 `chatJSON` HTTP
helper 抽到独立的 `providers/http.ts`，让 `mock.ts` 回归"零网络、自包含的
离线 demo / 测试 fixture"单一职责，并清掉 mock 顺手再导出的
`validatePlanResponse`（调用方本就直连 `prompt.js`）。`openai.ts` 与
`ollama.ts` 改从 `./http.js` 引入 `chatJSON`，`index.ts` barrel 同步暴露
`http.ts`。`deepseek.ts` 保持自有 SSE 流式客户端不动（其语义与 `chatJSON`
的非流式 POST 不同）。同步更新 `AGENTS/ai-integration.md` 与
`packages/ai/README.md` 中"添加 provider / 公开 API"两处的目录职责说明。

动机：mock 是"deterministic, zero-network"的 demo provider，原本却承担了
真实 provider 的共享 HTTP 工具仓库角色——这是结构边界泄漏，违反
AGENTS/ai-integration.md 对 mock 的定位与 AGENTS/conventions.md
"Adding an import that would create a cycle means the code is in the wrong
package — move it" 的同源原则（模块层）。重构后 mock 不再被任何真实
provider 导入，可独立审视、删除或替换。

## 设计决策（关键取舍）

1. **BaseHttpProvider 服务范围**：仅服务于「OpenAI-compatible HTTP + key auth
   - GET /models 发现」这一族（openai + deepseek）。`ollama` 是 local-probe
     模式（无 key，isAvailable 探测服务器），不继承基类；`mock` 自包含不动；
     `zai` SDK 路径不动。基类是扩展点，未来新的 key-auth HTTP provider 可直接复用。
2. **DeepSeek override listModels**：基类 `listModels()` 抛
   `DeepSeek model listing failed (HTTP 401): ...`，但 DeepSeek 测试 snapshot
   pin 了 `/DeepSeek API error 401.*auth failed/`（来自 `apiErrorMessage()`）。
   因此 DeepSeek `override listModels()` 保留自有错误格式。基类行为通过
   OpenAIProvider 覆盖。
3. **ToolDefinition 新字段为可选**：`mutates?` / `dryRunDefault?` 默认 `false`
   当 absent。向后兼容——既有 skill/plugin tool 不需要标注。`listToolSummaries()`
   归一化为 boolean（`tool.mutates === true`）。
4. **catalog 渲染格式变更不影响 plan 契约**：`renderToolCatalog()` 输出文本变
   （分组 + 标签），但 `planSchema` / `validatePlanResponse` / `reviewPlan` 全部
   不变。Mock provider 的 plan 输出（`file.find` step）字节级不变——snapshot 保留。
5. **UI main-info-first**：SidePanel Tools tab 顶部加 catalog overview 行，
   让用户一眼看到 catalog 规模 + read/mut/dry 分布；family header 带 count；
