# 内置工具

Tau 的工具层是**确定性**的：每个工具都是纯注册表驱动的函数，AI 计划只能调用注册表里存在的工具，不存在"AI 现场发明工具"。内置工具分四族，全部低风险只读优先、可变操作默认干跑。

## file 族 —— 文件系统

| 工具          | 说明                                                                                       | 风险   |
| ------------- | ------------------------------------------------------------------------------------------ | ------ |
| `file.find`   | 按 glob 递归查找（自动剪枝 node_modules/.git/dist）                                        | low    |
| `file.read`   | 带行号读取文本文件（offset/limit、拒绝二进制与 >2MB；v0.5.0 起结构化结果携带检测到的语言） | low    |
| `file.list`   | 单目录非递归列表                                                                           | low    |
| `file.stat`   | 大小 / 类型 / mtime                                                                        | low    |
| `file.tree`   | 深度受限的目录树                                                                           | low    |
| `file.rename` | 正则批量重命名（默认干跑）                                                                 | medium |
| `file.write`  | 受控写入（覆盖/追加，默认干跑，硬限制在工作区内）                                          | medium |

**刻意没有 delete。** 第一方工具族里不存在删除原语——删除只能走经审查的 shell 步骤或你自己的手。这是写在安全模型里的设计决策，不是遗漏。

## sys / net / text 族

- **sys**：进程、磁盘、环境等系统只读探查。
- **net**：HTTP GET 等网络只读操作。
- **text**：在文件内容上做查找、统计等文本操作。

每个工具在 CLI 都有对应命令（如 `tau file read`），也可以在 WebUI 的 Tools 面板浏览全部参数 schema。

## 风险与确认

工具声明的 `risk` 决定执行门的宽严：low 只读工具在计划里可直接运行；medium 工具（写操作）默认干跑预览，设置 `execute: true` 才真正生效；安全审查层还会对计划里的每个写路径做独立复核（纵深防御——审查只会加强工具自身的检查，不会放松）。

## file.read 的语言元数据（v0.5.0）

`file.read` 的结构化结果现在携带 `path` 与 `language`——从文件名做最佳努力的语言推断（shiki 兼容 id，未知回落 `text`）。WebUI 的文件查看器用它选择高亮语法，工具层与前端共享同一份检测逻辑，由一致性测试防漂移。
