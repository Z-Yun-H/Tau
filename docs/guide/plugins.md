# 插件（MCP）

插件把外部工具服务器接进 Tau：通过 Model Context Protocol（MCP），任何实现该协议的工具服务器都能把它的工具注册进 Tau 的工具注册表，AI 计划即可调用。

## 基本用法

```bash
tau plugin add <command-or-url>   # 注册一个 MCP 服务器
tau plugin list                   # 查看已注册插件
```

Tau 内置 MCP 客户端层（`@tau/plugins`），通过 stdio/HTTP 与服务器通信。插件注册的工具在目录里以插件名为前缀呈现，与内置工具共用同一套计划-审查-执行管线。

## 安全规则：插件工具永远是 medium risk

这是刻意的底线：来自外部服务器的工具，Tau 无法审查其内部实现，因此**一律**按 medium 风险对待——它们永远不能静默自动执行，必须经过与写入操作相同的确认门。插件扩展的是能力面，不是信任面。

## 技能还是插件？

|      | 技能                     | 插件               |
| ---- | ------------------------ | ------------------ |
| 形态 | 一个 SKILL.md 文档       | 独立工具服务器进程 |
| 工具 | 声明式命令（展开成意图） | 真实的可执行工具   |
| 风险 | 声明制，走审查           | 一律 medium        |
| 适合 | 提示注入、流程约定       | 真正的外部系统能力 |

需要零代码注入选[技能](/guide/skills)；需要接真实的系统选插件。

## 故障排查

插件不可达时 Tau 会诚实降级：该插件的工具从目录中移除并附说明，其余管线照常。`tau plugin list` 显示每个插件的可用性；网络型服务器注意检查 URL 与认证环境变量。
