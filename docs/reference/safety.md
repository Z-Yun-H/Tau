# 安全模型

Tau 的安全设计围绕一句话：**AI 提议，规则审查，人来拍板。** 全部机制都是确定性代码，没有"AI 觉得没问题"这种环节。

## 三道门

1. **计划校验**——provider 输出必须是严格 JSON（zod schema，`additionalProperties: false`），宽松输出（含代码围栏、多余字段）直接拒绝。
2. **确定性审查**——`reviewPlan()` 按规则给计划定级：allow / review / deny，附逐条 issue。审查者独立复核每个写路径，与工具自身的检查形成纵深防御。
3. **执行确认**——deny 不可运行；high-risk 需要显式确认（CLI 交互确认、WebUI 卡片级勾选）；medium 写操作默认干跑，`execute: true` 才生效；agent 模式下 medium+ 轮次内联暂停等待批准，**永远没有一次性预授权**。

## 执行通道唯一

`runPlan()` 是唯一执行通道，内部还会**再次**审查。任何界面（CLI/TUI/WebUI）、任何模式（ask/goal）、任何 provider，最终都汇到这里。不存在"provider 直接跑命令"的路径。

## 具体的硬边界

- **没有 delete 工具**：第一方工具族刻意不提供删除原语。
- **工作区围栏**：`file.write` 拒绝工作区外路径与系统位置（`/etc`、`/usr` 等），二进制目标与 >2MB 内容拒绝。
- **插件工具一律 medium**：外部 MCP 工具不可审查内部实现，风险等级不因插件声明而降低。
- **shell 步骤可中止**：中止会杀掉整个进程组，不会留下孤儿进程。
- **AI 永不自我评分**：反思产生的下一轮计划同样要过确定性审查；反思只是提议，审查才是门。

## 流式不削弱安全（v0.5.0）

流式规划只改变文本"何时到达"，不改变"如何被处理"：流式组装出的计划仍走同一个 `validatePlanResponse()` 与 `reviewPlan()`；拒绝发生在流开始之前（纯 JSON 错误），不存在"流式绕过审查"的形态。

## 可观测性

每次请求一行结构化日志（含 AI token 成本），WebUI 设置面板只展示脱敏配置——API key 永不明文出现在日志或浏览器。
